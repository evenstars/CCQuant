# CCQuant — 美股横截面动量策略设计文档

> 版本 v0.1 · 2026-06-07
> 目标:实现一个**可回测、可风控、可实盘、可监控**的低频量化策略。
> 第一阶段策略:**美股纯多头横截面动量(月度调仓)+ 大盘趋势刹车 + 分批建仓**。

标普 500 年内约 +10%,6 月初创新高 7600 后一周回调 2.6%,VIX 单日跳涨 34% 至 20 上方,RSI≈69 接近超买;但价格仍在 50/200 日均线之上。动量因子今年是最强因子之一(MTUM 年内约 +12%)。

## 1. 策略规范(Strategy Spec)

### 1.1 核心逻辑

横截面动量 = 在一篮子股票里**互相排名**,买过去表现最强的一批,定期换仓。与时间序列趋势(跟自己的过去比)不同,它始终满仓持有"相对最强"的标的。

### 1.2 信号定义

- **股票池(Universe):** S&P 500 成分股(用历史成分,避免幸存者偏差),按流动性过滤:20 日平均成交额 > $5M,价格 > $5。
- **动量打分:** 经典 **12-1 动量** = 过去 12 个月收益剔除最近 1 个月(`ret(t-12m → t-1m)`)。剔除最近 1 个月用于规避短期反转效应。
- **可选增强(v1.1):** 用**风险调整动量**(过去 12 个月收益 / 同期日收益波动率)降低波动拖累;或加 **52 周高点距离** 作为辅助因子。
- **排名与选股:** 按动量打分降序,取**前 10–15%**(初期资金小则固定取 **15 只**)。
- **权重:** 等权(每只 ≈ 1/N)。碎股保证精确等权。
- **调仓频率:** **月度**。月末收盘计算信号,次日开盘执行。

### 1.3 趋势刹车(Regime Filter)

- 计算 SPY 的 200 日均线(SMA200)。
- **大盘在 SMA200 之上 → 满仓**(绿灯)。
- **大盘跌破 SMA200 → 降仓**(黄/红灯):仓位降至 50%(或仅持有动量打分仍为正者),其余转现金/SHV(短债 ETF)。
- 目的:避开动量崩盘最惨的"市场剧烈反转 + 强势股踩踏"阶段。这是纯多头版躲熊市的唯一手段。

### 1.4 进出场细则

- **分批建仓(冷启动):** 首次建仓不一次性满仓。按计划资金 1/3 → 1/3 → 1/3,分 3 个月度调仓铺满,避免在高位一次吃满回调。
- **换仓规则:** 每月重排名,卖出跌出目标名单的、买入新进入的;名单内继续持有,减少不必要换手(降低税与成本)。
- **执行:** 次日开盘 Market-on-Open(MOO);大单可拆分或用 VWAP/TWAP 算法单(IBKR 支持)。

### 1.5 参数表(集中管理,见 `config/strategy.yaml`)

```yaml
universe: SP500
lookback_months: 12
skip_recent_months: 1
n_holdings: 15
weighting: equal
rebalance: monthly            # 月末信号,次日开盘执行
regime_filter:
  benchmark: SPY
  ma_window: 200
  below_ma_exposure: 0.5      # 跌破200日均线时的目标仓位
ramp_in_tranches: 3           # 分批建仓批次
liquidity:
  min_adv_usd: 5_000_000
  min_price: 5
```

## 2. 回测框架(Backtesting)

### 2.1 设计原则

回测的唯一目的是**诚实地估计未来,而不是把历史曲线调好看**。因此:

- **避免幸存者偏差:** 用含退市股的历史股票池与历史成分名单。
- **避免前视偏差(look-ahead):** t 月末的信号只能用 ≤ t 的数据;执行价用 t+1 开盘价,不能用收盘价"偷看"。
- **总收益口径:** 价格用复权(分红再投资、拆股调整)。
- **成本建模:** 佣金(IBKR 分级费率,约 $0.0035/股,最低 $0.35/单)+ 滑点(按价差与冲击,初期保守用 5–10 bps)+ 借券成本(纯多头无,v2 做空时加)。
- **税务建模(应税账户特有):** 分别记录短期/长期资本利得,按持有期切分税率,评估"税后"净收益(见第 6 节)。

### 2.2 流程

```
数据加载 → 股票池构建(按月) → 因子计算 → 排名选股 → 组合构建(含趋势刹车/分批)
→ 按月推进撮合(t+1开盘) → 计入成本 → 净值与持仓记录 → 绩效与归因
```

### 2.3 验证手段(防过拟合)

- **样本外 / 滚动 walk-forward:** 例如 2005–2018 训练观察,2019–2026 严格样本外。
- **参数敏感性:** 对 `lookback_months`(6/9/12)、`n_holdings`(10/15/20/30)做网格,看绩效是否平滑——**曲面平滑 > 单点最优**。
- **对照基准:** 必须跑赢 (a) SPY 买入持有,(b) 等权 S&P 500,(c) MTUM(动量 ETF),否则没有自建的理由。
- **多周期子样本:** 分别看牛市(2013、2017、2023–24)、熊市(2008、2022)、动量崩盘(2009-03、2020Q2)的表现。

### 2.4 绩效指标

CAGR、年化波动、**Sharpe / Sortino**、最大回撤(MDD)与回撤时长、Calmar、月度胜率、换手率、**税后 CAGR**、相对基准的信息比率(IR)。

### 2.5 输出

`backtest/reports/` 下生成:净值曲线、回撤曲线、滚动 Sharpe、年度收益表、持仓快照、与基准对比,导出 HTML/PDF 报告 + 指标 CSV。

## 3. 风险控制(Risk Management)

分三层:**信号层 → 组合层 → 执行/账户层**。

### 3.1 信号层

- 趋势刹车(SMA200)降低系统性风险敞口。
- 流动性过滤剔除难成交、易被操纵的小票。
- 剔除财报日临近(±2 交易日可选)新建仓,降低事件跳空风险。

### 3.2 组合层

- **等权 + 单票上限:** 单票权重 ≤ 1/N(等权天然满足),硬上限 8%。
- **行业/板块集中度上限:** 单 GICS 行业 ≤ 35%,避免动量扎堆(如全是半导体)。
- **现金缓冲:** 保留 1–2% 现金应对碎股/费用。
- **波动率目标(v1.1 可选):** 组合年化波动目标 15%,超过则按比例降杠杆/降仓。

### 3.3 执行 / 账户层

- **个股止损?** 横截面动量**不建议**用个股硬止损(与月度再平衡逻辑冲突,且增加换手与税)。风险由"月度换仓 + 趋势刹车"统一管理。
- **组合级断路器(circuit breaker):** 若组合从近高点回撤 > 25%,触发人工复核(暂停自动加仓,人工确认是否降仓)。
- **下单防呆:** 单笔订单金额 / 数量上限校验;偏离参考价 > X% 拒单;重复下单去重;盘前检查可用资金与持仓一致性。
- **PDT 规避:** 月度低频天然不触发 Pattern Day Trader;但代码层禁止同日反复买卖同一标的。
- **故障安全:** API 断连 / 数据异常 → 不下单、告警、保持现状(fail-safe,绝不"盲下")。

### 3.4 风控参数(`config/risk.yaml`)

```yaml
max_position_weight: 0.08
max_sector_weight: 0.35
cash_buffer: 0.02
portfolio_drawdown_alert: 0.25
order_price_deviation_reject: 0.03   # 偏离参考价3%拒单
vol_target_annual: null              # v1.1启用,如0.15
```

## 4. 实盘执行(Live Trading — IBKR)

### 4.1 架构

```
调度器(月度cron) → 信号引擎(复用回测同一份因子代码)
  → 目标组合 → 与当前IBKR持仓做diff → 生成订单
  → 风控预检(pre-trade checks) → ib_insync下单(MOO/算法单)
  → 成交回报 → 持仓/现金对账 → 落库 → 通知
```

**关键原则:回测与实盘共用同一套信号与组合构建代码**(`strategy/`),只是数据源和"撮合"换成实盘 API。这样消除"回测能赚、实盘不一样"的代码偏差。

### 4.2 IBKR 接入

- **连接:** IB Gateway(无头,适合自动化)或 TWS;`ib_insync` 异步 API。
- **环境:** 先连 **Paper Trading 账户**跑通全流程(纸上实盘 ≥ 1–2 个调仓周期),再切真实账户。
- **下单类型:** 次日开盘 MOO 单为主;大额或流动性差时用 IBKR Adaptive / VWAP 算法单。
- **碎股:** IBKR 支持碎股,保证小资金下精确等权。
- **对账:** 每次调仓后拉取 `reqPositions` / `reqAccountSummary`,与目标组合和本地账本核对,差异 > 阈值即告警。

### 4.3 执行流程(月度)

1. 月末收盘后:拉数据 → 算信号 → 生成目标组合(含趋势刹车与分批阶段)。
2. 生成 trade list(diff)→ 风控预检 → 人工确认(初期保留 human-in-the-loop)。
3. 次日开盘:提交订单 → 监控成交 → 处理未成交/部分成交(超时撤改)。
4. 收盘后:对账 → 记录实际成交、成本、滑点 → 更新持仓账本 → 发送调仓报告。

### 4.4 安全与运维

- 凭证用环境变量 / 密钥管理,不入库不进 git。
- 幂等:同一调仓周期重复运行不重复下单(用调仓批次 ID 去重)。
- 所有订单与成交持久化(SQLite/Postgres),可审计、可复盘。
- `kill switch`:一键停止所有自动下单。

## 5. 监控与告警(Monitoring)

### 5.1 监控对象

- **系统健康:** 调度任务是否按时跑、IBKR 连接状态、数据源是否更新、上次成功调仓时间。
- **执行健康:** 订单状态(已报/成交/部分/拒单)、实际滑点 vs 预期、未成交超时。
- **组合健康:** 实际持仓 vs 目标(漂移)、现金、当前回撤、行业集中度、是否触发趋势刹车/断路器。
- **绩效跟踪:** 每日净值、月度收益、与 SPY/MTUM 实时对比、滚动 Sharpe。
- **数据质量:** 缺失/异常价格、复权跳变、成分名单更新。

### 5.2 告警

- 渠道:邮件(`chang.liu159@gmail.com`)+ 可选 Slack/Telegram webhook。
- 分级:INFO(调仓完成报告)/ WARN(滑点偏大、轻微漂移)/ CRITICAL(API 断连、拒单、断路器触发、对账不符)。
- CRITICAL 必须人工介入,系统进入 fail-safe(不下单)。

### 5.3 可视化

- 一个本地/轻量 dashboard(可后续做成 Cowork artifact 或简单 Streamlit):净值曲线、当前持仓表、回撤、趋势灯(绿/黄/红)、近一次调仓明细、告警列表。
- 月度自动生成 PDF 报告归档到 `monitor/reports/`。

## 6. 税务处理(应税账户专属)

应税账户里,**税后收益**才是真收益,月度换手会产生大量短期资本利得(按普通所得征税)。设计上:

- **持有期感知:** 记录每个 lot 的买入日;调仓时**优先卖出会变长期(>365 天)的或亏损 lot**,在不破坏策略前提下降低短期利得。
- **Wash sale 规避:** 卖出亏损标的后 30 天内禁止买回同一/实质相同标的(代码层硬约束)。
- **税损收割(tax-loss harvesting):** 年末对浮亏标的择机实现亏损抵税,用相关但非"实质相同"标的替代以维持敞口。
- **换手控制:** 名单内继续持有、设置打分"缓冲带"(进入需排名前 15,跌出需掉出前 25 才卖),减少边缘换手 → 同时降税降成本。
- **报表:** 年度生成已实现盈亏(短期/长期分列)汇总,便于报税与评估税后 alpha。

> 这是纯多头月度动量在应税账户最大的隐性成本,务必在回测里用**税后口径**评估,否则会高估策略价值。

## 8. 实施计划(里程碑)

分阶段交付,每阶段都有可验证产物。**重点不是一上来赚钱,而是先证明策略有税后 alpha、且能机械执行。**

### M0 — 脚手架(0.5 周)
项目结构、配置体系、日志、数据缓存框架、CI/测试骨架。**产物:** 能跑通 `pytest` 的空管线。

### M1 — 数据层(1 周)
接入数据源(MVP: yfinance;正式: Polygon/Norgate 含退市股),实现复权、历史成分股票池、流动性过滤、缺失值处理。**产物:** 可复现的、无幸存者偏差的历史价格与股票池。

### M2 — 回测引擎 + 策略(1.5 周)
实现 12-1 动量、排名选股、等权组合、趋势刹车、分批建仓;t+1 开盘撮合;成本与**税务建模**;绩效与归因报告。**产物:** 对照 SPY/等权/MTUM 的回测报告 + 参数敏感性曲面 + walk-forward 结果。**Gate:** 税后是否仍跑赢基准?不行就调整或止步。

### M3 — 风控模块(0.5 周)
组合约束、断路器、下单防呆、wash-sale 与持有期逻辑,接入回测与实盘前置检查。**产物:** 风控单元测试全绿。

### M4 — 实盘接入(IBKR Paper)(1 周)
`ib_insync` 连接、目标组合 diff、下单(MOO/算法单)、成交回报、对账、幂等与 kill switch。先在 **Paper 账户**跑 ≥ 1–2 个调仓周期。**产物:** 纸上实盘完整调仓 + 对账无差异。

### M5 — 监控与告警(0.5 周)
健康检查、分级告警(邮件)、dashboard、月度报告。**产物:** 调仓自动出报告 + 异常能告警。

### M6 — 小资金真实盘(<$25k)(持续)
切真实账户,**分批建仓(3 个月铺满)**,保留 human-in-the-loop 确认。跑 6–12 个月,目标是验证执行纪律与实盘 vs 回测一致性,而非短期收益。**Gate:** 实盘滑点/成本/税后收益是否与回测吻合?吻合且有 alpha → 考虑加码或进入 v2。

## 9. 主要风险与对策(汇总)

| 风险 | 对策 |
|---|---|
| 过拟合(回测好、实盘差) | walk-forward、参数曲面平滑、回测/实盘共用代码、对照基准 |
| 动量崩盘 | 200 日均线趋势刹车、分批建仓、组合断路器 |
| 应税账户税负侵蚀收益 | 税后回测口径、持有期优化、wash-sale 规避、换手缓冲带 |
| 幸存者/前视偏差 | 含退市股票池、历史成分、t+1 开盘撮合、复权口径 |
| 执行/技术故障 | Paper 先行、幂等、对账、fail-safe、kill switch、分级告警 |
| 心理/纪律(中途放弃) | 先小资金验证执行力、月度机械调仓、自动报告减少手动干预 |
